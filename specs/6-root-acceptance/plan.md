# Root acceptance delivery

One implementation slice owns project bootstrap, shared types, root acceptance and theorem, semantic trust counterexample, simulator, permanent gates/CI and matching documentation. The ticket owner owns planning and acceptance; commit owner owns implementation/local commits; persistent auditor independently reads committed checkpoints and mechanical receipts. No extra seats or draft tools.

Policy supplies explicit abstract verification observations and executable agreement. SigValid is a Prop hypothesis at the proof boundary, with observation soundness explicit. Observation evaluation implements no signatures. A different public signature or extra trust assumption returns as a contract question.

Checkpoints: complete RED bundle, each of six acceptance rows, pre-push. A bootstrap row without an executable subject is COULD-NOT-EVALUATE, not behavioral RED. The subset-check mutation must compile and have a constructive refutation. Auditor runs no gates. Push requires every checkpoint approved.

Required checks: check-model, check-docs, just ci, pinned Lake commands and frozen scenario/mutation commands. Bind commands, exit, clean SHA/tree and evidence hashes.

Finish with accepted task stamp, final commit tree comparison, exact-head gates, draft PR, exact-head remote CI, finalization audit and ready-for-review handoff. Bootstrap push is deferred until the brief's audit/gate push fence is met. Revision consumption with main documentation publication is the accepted release path; binaries remain future debt.

Ceilings: each planning file <= 100 lines/10 KB; packet <= 200 lines/18 KB; implementation <= 1800 changed lines excluding generated Lake manifest. Resource tiers: 180 cheap invocations, 20 expensive gates; no native goal token limit. Stop before overrun and ask parent with receipts.
