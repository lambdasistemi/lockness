# Operating context plan

As a reviewer, see how the context guard enters the accepted fold and the verdict. Behaviour changes only where the ruling names it.

## Strategy

1. Extend the shared types exactly as released: `Context`, `Policy.context`, `MessageModel`, `MessageBinding`.
2. Add the guard (selected-point network and selected-root scheme; foreign publications ignored, ruling C1) and the context-checked root acceptance; `accept` binds its root through it. Inherited accept statements keep their text; their proofs adapt.
3. Classify an out-of-context refusal as `refused` before the declared-absence reasons. Restate only `unbound_only_unverified`, as ruled.
4. Adapt the four positional inherited policies with the neutral context, so every inherited outcome is unchanged.
5. Add the context statements, the guard theorems and context soundness; the fixtures with two abstract-model instances; the refutations; the finite tests.
6. Add the compiled mutation script, the five `context` scenarios, the usage text and the model-gate stages.
7. Update the reader-facing documentation and curated speech. Publish an immutable model commit, then a forward source-pin documentation commit.

## Constraints

- Fence as ruled; every frozen file stays byte-identical to acbde08.
- An elaborated-statement inventory diff against acbde08 shows exactly the ruled restatements, generated declarations, compiler auxiliaries and neutral-value text.
- Every inherited scenario's stdout line and every inherited stage outcome is unchanged.
- No concrete network identifier, signature or message encoding, protocol-parameter semantics, key rotation, `act`, settlement or binary release.
- Every local gate runs with CI's restricted PATH (nix, bash and dirname only) on a warmed dependency cache.

## Evidence and limits

The required checks are the CI commands `./tools/check-model.sh` and `./tools/check-docs.sh`, the Docs build job and the PR preview, all on the exact pushed head.

Invocations are counted from receipts and checked before each run. Proposed limits: expensive tier 40 (Nix, full check-model, check-docs, CI), cheap tier 250 (single-file lean, single scenario); 900 s per command. Phase 1 baseline and setup receipts are counted separately.

Remote main is refreshed before the final verification cycle and before readiness. A moved base is integrated by a history-preserving merge.
